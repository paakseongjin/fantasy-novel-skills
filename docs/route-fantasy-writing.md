# 자연어 요청에 따른 스킬 조합·라우팅

`route-fantasy-writing`은 기존 창작 스킬 17개에 추가하는 조합 전용 스킬입니다. “다음 화를 구성해서 써 줘”, “대사만 고쳐 줘” 같은 요청에서 필요한 스킬과 순서를 고르고 결과를 이어 줍니다. 특정 작품이나 외부 저장 공간에 의존하지 않습니다.

## 설치

[Gemini ZIP](../dist/gemini/route-fantasy-writing.zip) · [Claude ZIP](../dist/claude/route-fantasy-writing.zip) · [ChatGPT ZIP](../dist/chatgpt/route-fantasy-writing.zip) · [프로젝트용 문서](../dist/chatgpt-project/route-fantasy-writing.md) · [편집 원본](../skills/route-fantasy-writing/SKILL.md)

기존 스킬을 등록했다면 이 개별 ZIP 하나만 추가합니다. Gemini에서는 Customize → Skills → Create → Upload로 등록하고 활성화 상태를 확인합니다. 동일 이름의 이전 라우터가 있다면 기존 항목의 Replace skill로 교체해 중복을 피하세요. 기존 17개 창작 스킬의 재등록은 필요하지 않습니다.

라우터 ZIP에는 라우팅 지침과 선택표·조합 예시가 들어 있습니다. 다른 25개 전문 스킬 본문을 포함하거나 자동 설치하지 않습니다. 분야별 선택형 8개가 없어도 등록된 `build-fantasy-world`의 관련 지침을 활용합니다. 요청에 필요한 전문 스킬이 실제로 읽히지 않으면 적용 여부를 구분해 알립니다.

## 사용 예시

```text
route-fantasy-writing을 적용해 다음 요청에 필요한 스킬을 골라 진행해 줘.
아래 9화에 이어 10화의 장면 구성과 초고를 써 줘.
주인공 시점, 이미 정해 둔 결말과 공개하지 않을 비밀은 유지해 줘.
[직전 원고 / 확정 설정 / 10화 목표 / 분량]
```

활성화된 뒤에는 자연어 요청만으로 자동 선택될 수 있습니다. 처음 확인할 때는 `/` 또는 지원되는 화면의 `@`에서 라우터를 선택하거나 이름을 명시하세요. 한 단계만 필요하면 기존 전문 스킬을 직접 사용해도 됩니다.

| 요청 | 의도한 작동 |
|---|---|
| “다음 화 방향만 세 가지, 본문은 쓰지 마” | 회차 기획만 수행 |
| “대사와 두 사람의 갈등을 함께 고쳐 줘” | 갈등 원인을 정리한 뒤 대사에 반영 |
| “내용을 바꾸지 말고 번역투만 없애 줘” | 한국어 퇴고만 수행 |
| “설정집과 원고가 충돌하는지 확인해 줘” | 정전 감사, 양쪽 근거 대조 |

## 공식 근거와 설계의 구분

확인일: 2026-11-15.

- [GitHub 공식 Agent Skills 문서](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-skills): `SKILL.md`, `name`·`description` 메타데이터, 보조 자료 구조와 요청에 따른 선택 방식을 참고했습니다. 저장소의 `skills/`는 배포 원본 경로이며 Copilot 자동 탐색 경로라고 주장하지 않습니다.
- [Agent Skills 규격](https://agentskills.io/specification): 이름·설명 형식과 필요한 참고 자료만 읽는 구조를 따릅니다.
- [Google 공식 Gemini Apps 도움말](https://support.google.com/gemini/answer/17094296?hl=en): 스킬 지침에서 다른 스킬을 참조하는 조합, 활성화된 스킬의 자동 적용, ZIP의 루트 `SKILL.md` 형식을 확인했습니다. Gemini CLI의 명령을 Gemini Apps 기능으로 혼용하지 않습니다.

어떤 창작 스킬을 어떤 순서로 연결할지는 이 저장소가 설계한 작업 규칙입니다. 공식 문서가 특정 소설 작업의 라우팅 정확성을 보장하는 것은 아닙니다. 사용자에게 기존 스킬 등록 완료를 확인받았지만, 이 새 라우터의 실제 Gemini 등록과 실행은 여기서 시험하지 않았습니다. GitHub에 푸시해도 이미 등록된 스킬은 자동 갱신되지 않습니다.

## 실행 시 확인할 사례

아래는 모델 행동을 확인하기 위한 수동 검증 시나리오이며, 실제 Gemini 통과 결과가 아닙니다. 사례별 새 대화에서 원고 등 입력을 제공하고 요청 범위·보존 조건·결과를 평가합니다. 스킬 이름을 말했는지만으로 통과시키지 않습니다.

| 입력 상황 | 기대 행동 | 실패 신호 |
|---|---|---|
| 직전 원고와 설정을 주고 다음 회차 기획·집필 요청 | 회차 목표·변화를 본문으로 연결 | 라우팅 표만 내고 집필하지 않음 |
| “방향 세 가지만, 본문은 쓰지 마” | 서로 다른 기획안으로 종료 | 하나를 확정하거나 초고 작성 |
| “가능성을 유지해: 그는 문을 열 수 있었다. 끝내 손잡이를 잡지 않았다” | 가능성과 미실행 보존 | 실제로 문을 연 사건으로 변경 |
| 고정된 승패·부상 조건의 추격전 수정 | 동선과 인과 개선, 결말 유지 | 새 마법·무기로 문제 해결 |
| 독자만 아는 비밀이 있는 갈등 장면 수정 | 인물 지식 범위 안의 행동·대사 | 당사자가 비밀을 이미 아는 대사 |
| 실제 단서 없이 반전 계획만 제공 | 계획과 원고 속 단서 구분 | 과거에 단서를 심었다고 주장 |
| 세계관 선택형 없이 통합형만 등록 | 통합형의 해당 자료 적용 | 미설치 분야별 스킬 호출 완료 주장 |
| 라우터만 있고 전문 스킬 지침은 접근 불가 | 선택·자료 안내와 일반 작업 구분 | 이름만 나열하고 전문 지침 열람 주장 |
| 설정집 없이 원고 모순 검사 요청 | 원고 내부 모순으로 범위 제한 | 설정집까지 대조했다고 보고 |
| “진단만”이라는 원고 검토 요청 | 근거·문제·수정 방향으로 종료 | 원고를 재작성·저장 |
| 이미 해결한 문제를 다른 스킬이 다시 라우터로 보냄 | 결과 재사용, 필요한 추가 작업만 | 무한 재선택·반복 감사 |
| 소설과 무관한 날씨 질문 | 소설 스킬 라우팅 생략 | 창작 스킬을 억지로 조합 |

자동 검사는 25개 대상 이름의 실제 존재, 통합형 대체 자료의 존재, 패키지 내부 링크, ZIP 무결성·원본 일치와 생성물 재현성을 확인합니다. 모델의 자연어 분류 정확성은 별도 검증 대상입니다.
