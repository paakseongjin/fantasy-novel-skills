# 스킬 선택표

등록된 스킬의 정확한 이름으로 적용한다. 이 표는 역할 안내이며 전문 지침의 대체물이 아니다. 해당 스킬의 지침을 읽을 수 없으면 적용했다고 주장하지 않는다.

## 기본 창작 스킬 17개

| 스킬 | 선택할 때 | 입력 → 다음 단계에 전달할 결과 |
|---|---|---|
| `build-fantasy-world` | 여러 세계관 분야를 연결하거나 분야별 선택형이 없을 때 | 전제·확정 설정 → 관련 분야 설계, 생활·권력·갈등의 연결, 제안 표시 |
| `plan-fantasy-longform` | 작품 전체의 인과·이야기 단위·결말을 설계할 때 | 목표·기존 줄거리 → 사건 인과와 장기 구조 |
| `design-character-arcs` | 장기적인 신념·관계 변화와 성장의 계기를 설계할 때 | 출발 상태·갈등 → 선택·대가·변화의 단계 |
| `manage-fantasy-foreshadowing` | 단서 배치·비밀·반전·정보 공개·회수를 다룰 때 | 실제 단서와 계획 → 독자/인물 지식 구분, 공개·회수 후보 |
| `structure-serial-chapters` | 회차 목표·분할·장면 배치·다음 회차 연결을 잡을 때 | 전후 사건·분량 조건 → 회차별 시작·목표·변화·종료 상태 |
| `write-fantasy-prose` | 장면·회차의 실제 본문을 쓰거나 이어 쓸 때 | 확정 자료·시점·목표 → 본문과 미확정 추가 설정 |
| `write-character-conflict` | 현재 장면의 심리·관계 갈등과 선택이 설득력 없을 때 | 욕구·두려움·힘의 차이 → 행동과 선택의 인과 |
| `write-immersive-scenes` | 공간·위치·이동·감각이 불분명할 때 | 공간 조건·관점·동선 → 장면을 따라갈 수 있는 묘사 |
| `design-fantasy-action` | 전투·추격의 목표·전술·승패 원인을 설계할 때 | 능력·제약·공간 → 행동-대응-대가-결과 |
| `craft-character-dialogue` | 인물별 말투·호칭·존대·대사 속뜻을 다듬을 때 | 관계·지식·대화 목적 → 구분되는 대사와 전달 정보 |
| `refine-natural-korean` | 어휘·호응·번역투·반복 등 문장을 다듬을 때 | 원문·수정 수준 → 의미와 목소리를 보존한 수정본 |
| `review-fantasy-manuscript` | 어디가 문제인지 불명확한 원고의 구조·인과·독자 이해를 진단할 때 | 원고·검토 범위 → 근거 있는 문제, 우선순위, 최소 수정 방향 |
| `audit-fantasy-canon` | 확정 자료와 원고의 연표·지식·능력·이동·소지품을 대조할 때 | 적용 시점이 있는 설정과 원고 → 양쪽 근거, 충돌 후보와 최소 수정안 |
| `design-reader-attachment` | 인물·관계에 대한 독자의 관심과 애착을 설계할 때 | 인물·관계·독자 약속 → 행동·관계 장면과 애착 계기 |
| `lower-opening-barrier` | 프롤로그·초반의 정보 과부하와 진입장벽을 점검할 때 | 초반 원고·필수 정보 → 남길 정보와 미룰 정보, 시작 개선안 |
| `prevent-serial-drag` | 중후반의 반복·목표 정체·연재 피로를 개선할 때 | 여러 회차·장기 목표 → 반복 기능, 목표 변화와 축약·재배치안 |
| `audit-dropout-risks` | 독자 이탈 위험을 여러 축에서 종합 진단할 때 | 원고·독자 약속·실제 반응 → 근거별 위험과 개선 우선순위 |

## 겹치는 역할을 고르는 기준

- 전체 줄거리 인과는 장편 구성, 한 회차의 배치는 회차 구성, 이미 쓴 원고의 불명확한 문제는 원고 진단을 우선한다.
- 현재 장면의 심리는 갈등, 여러 회차에 걸친 변화는 인물 성장, 독자가 관계에 관심을 갖는 계기는 독자 애착을 우선한다.
- 전투가 왜 그렇게 끝나는지는 액션, 누가 어디에 있는지는 장면 묘사를 우선한다. 둘 다 필요할 때만 조합한다.
- 세계관 요소끼리의 설계 연결은 세계관 감사, 작품의 실제 자료와 다른지는 정전 감사다. 같은 근거의 충돌을 중복 보고하지 않는다.
- “지루하다”만으로 모든 연재 스킬을 실행하지 않는다. 초반 정보 과부하인지, 중후반 목표 정체인지, 원고 전반의 문제인지 구분한다. 불명확하면 원고 진단부터 한다.
