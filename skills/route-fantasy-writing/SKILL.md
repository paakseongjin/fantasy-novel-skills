# 판타지 집필 스킬 라우터

사용자의 요청을 실제 창작 결과로 완수하기 위해 등록된 전문 스킬의 역할과 순서를 조정한다. 특정 작품, 저장소 접속, 외부 저장 공간 없이 사용할 수 있다. 이 스킬은 다른 스킬을 설치하는 프로그램이 아니다.

## 1. 요청의 범위를 정한다

- 최종 결과가 아이디어·기획·본문·수정본·진단 중 무엇인지, 대상이 작품 전체·여러 회차·한 회차·장면·문장 중 무엇인지 파악한다.
- 반드시 유지할 사건·결말·시점·말투·정보 공개 범위와 수정 허용 수준을 먼저 잠근다. “구상만”, “오탈자만”, “진단만”, “본문만” 같은 제한은 모든 후속 단계에 전달한다.
- 사용자가 선택한 스킬과 제외한 작업을 우선한다. 명백한 단일 작업은 담당 스킬 하나로 처리하고 조합 절차를 늘리지 않는다. 소설과 무관한 요청에는 이 목록을 억지로 적용하지 않는다.
- 자료가 충분하면 바로 진행한다. 핵심 원고가 빠졌거나 서로 다른 확정 자료 중 어느 것을 따를지 몰라 결과가 달라질 때만 필요한 자료나 결정 하나를 묻는다. 자료 없이 가능한 아이디어는 가정을 표시해 제안할 수 있다.

## 2. 필요한 스킬만 선택한다

[스킬 선택표](references/skill-catalog.md)에서 작업에 해당하는 행을 읽는다. 기본 창작 스킬 17개와 선택형 세계관 스킬 8개는 **후보 목록**이다. 목록에 있다는 이유만으로 설치·활성화·열람을 완료했다고 간주하지 않는다.

- 최종 산출물을 책임질 주 스킬 하나를 정하고, 별도의 문제가 있는 부분에만 보조 스킬을 붙인다. 보통 1~3개면 충분하지만 복합 요청은 필요한 만큼 단계를 나눈다.
- 다른 스킬은 정확한 이름으로 참조하고, 현재 서비스가 제공하는 스킬 적용 기능으로 사용한다. 현재 대화에 이미 적용된 지침은 다시 요청하지 않는다. 읽을 수 있는 실제 지침과 요청에 필요한 참고 자료만 적용한다.
- 지침을 불러올 수 없다면 호출 API·명령을 만들어내거나 이름만 나열하고 “적용 완료”라고 하지 않는다. 스킬 선택 또는 해당 지침 제공을 안내하고, 독립적으로 가능한 부분은 일반 작업으로 진행하되 전문 스킬 적용과 구분한다.
- 세계관 분야별 스킬이 없으면 `build-fantasy-world`의 해당 분야 지침으로 처리한다. 통합형과 개별형으로 동일 설정을 이중 설계하지 않는다.
- 전문 스킬에서 다른 스킬을 추천하더라도 실제 요청에 필요할 때만 추가한다. 같은 단계에서 이미 처리한 문제로 라우터를 재호출하거나 스킬끼리 무한히 되돌리지 않는다.

## 3. 결과가 이어지는 순서로 실행한다

여러 작업을 결합할 때만 [조합 절차와 인계 규칙](references/composition-recipes.md)의 관련 예시를 참고한다. 예시의 모든 단계를 항상 실행하지 않는다.

일반적인 의존 순서는 **필요한 확정 자료 확인 → 요청된 기획·설계 → 요청된 본문 작성 → 요청된 수정·검토**다. 설정 충돌이 먼저 발견되면 해당 부분의 해결 전까지 그 충돌에 의존하는 집필을 보류한다. 여러 문체 스킬을 차례로 적용해 원문을 계속 재작성하는 대신 변경할 부분과 담당을 나눠 한 결과로 통합한다.

단계 사이에는 다음 정보 중 관련 항목만 넘긴다. 내부 작업 메모로 유지해도 되며 사용자에게 긴 보고서를 출력할 필요는 없다.

1. 목표와 수정 범위, 보존할 조건.
2. 실제 읽은 자료와 해당 위치·버전. 확인된 사실, 가정, 미확인 사항.
3. 앞 단계의 결과와 다음 단계가 사용할 부분. 제안인지 확정인지 표시.
4. 인물별 지식과 독자에게 공개된 정보, 장면 시작·종료 상태.
5. 다음 단계에서 해결할 문제와 완료 조건.

사용자가 후보 선택을 맡겼거나 최종 본문까지 요청했다면 필요한 선택을 가정으로 밝혀 진행한다. 사용자가 선택권을 유보한 줄거리·핵심 설정을 임의 확정하지 않는다. 기획 요청에서 본문 작성으로, 진단 요청에서 원고 수정으로 자동 확대하지 않는다.

## 4. 작품의 일관성을 지킨다

- 사용자 최신 지시와 명시적인 확정 자료를 우선한다. 버전·시점이 다른 자료의 충돌을 단순히 “최근 파일이 정답”으로 처리하지 않는다. 원고 속 인물의 발언은 거짓말이나 오해일 수 있다.
- 독자의 지식과 인물의 지식을 따로 추적한다. 복선 계획은 실제 심긴 단서와 구분한다. 예시 속 이름·마법·설정을 작품에 자동 편입하지 않는다.
- 문장 퇴고에서는 사건의 발생 여부·가능성·시제·관점과 인물 말투를 보존한다. 문체 변경만으로 설정 충돌이 해결됐다고 하지 않는다.
- 문피아 등 플랫폼 이름만으로 유료화 요건·권장 글자 수·독자 선호를 확정하지 않는다. 작가가 준 목표를 적용하고 현행 정책 확인이 필요한 요청만 공식 자료로 검증한다.
- 본문 작성, 설정 확정, 파일 저장, 플랫폼 발행은 각각 다른 작업이다. 요청·권한·실제 도구가 있는 범위에서만 수행하고 실제 결과를 확인한 작업만 완료로 보고한다.

## 5. 요청한 결과를 내고 끝낸다

조합이 도움이 될 때 “회차 구성 → 본문 집필 순서로 진행합니다”처럼 짧게 설명한 뒤 실제 결과를 낸다. 라우팅만 요청했다면 선택한 스킬·순서·필요 자료까지만 제시한다. “본문만” 요청에는 스킬 목록이나 작업 로그를 덧붙이지 않는다.

결과가 요청 범위를 충족하면 종료한다. 추가 검토는 요청됐거나 구체적인 미해결 문제가 있을 때만 수행한다. 확인하지 못한 자료와 결과에 영향을 주는 가정은 필요한 만큼만 밝힌다. 등록·자동 선택의 실제 성공 여부를 지침만으로 보장하지 않는다.
