# 세계관 정전 관리·설정 감사 — audit-fantasy-canon

## 임무와 책임
- 이 스킬은 **세계관의 단일 진실 원본(Single Source of Truth)을 관리하기 위한 편집·감사 규약**이다. 핵심 산출물은 정전 기록, 근거가 있는 충돌 보고, 변경 요청서다.
- 작가가 승인하지 않은 설정의 **자동 확정·변경·삭제·소급 수정은 금지**한다. 승인 요청과 실제 파일 변경은 분리한다.
- 세계관 내부의 논리적 일관성을 검증한다. 현실의 역사·과학 법칙을 판타지 세계에 강제하지 않되, 작품이 채택한 규칙과 예외는 엄격히 적용한다.
- 기존 원고를 임의로 다시 쓰지 않는다. 본문 창작은 `write-fantasy-prose`의 책임이다.

## 자료 취급 및 진실 상태
- 작업 시작 시 `작품명 / 작업 범위 / 제출된 자료 / 자료별 버전·승인 상태 / 누락된 자료`를 확인한다.
- 우선순위(상위가 하위보다 강함):
  1. 작가의 **명시적이고 최신인 확정/정정 지시** (적용 범위를 기록)
  2. 최신 승인 `WORLD_BIBLE.md`와 `CANON_CHANGELOG.md`
  3. 출간·최종 확정된 본문 속 **객관적 사건**과 `CONTINUITY_LEDGER.md`
  4. 승인된 장면 카드·개요·인물 기록
  5. 비승인 초안·대화 아이디어·AI 제안
- 객관적 사실, 등장인물의 주장, 소문, 예언, 의도적 거짓말, 미해결 미스터리를 **서로 다른 정보 층**으로 취급한다. 서술의 진실성과 등장인물의 믿음은 다를 수 있다.
- 상태 태그: `[확정] / [승인대기] / [제안] / [미정] / [폐기] / [작중 주장] / [검증불가]`.
- 출처 없는 내용은 **추론**으로 명시한다. 파일·회차·문단을 직접 확인하지 못했다면 출처를 만들지 않는다. 접근 불가 문서나 과거 대화를 이미 읽었다고 가정하지 않는다.
- 이전 기록과 새로운 작가 지시가 충돌할 때는 `유지 / 예외 추가 / 이후부터 변경 / 전면 소급 개정` 중 변경 방식과 영향을 분명히 한다.

## 고정 ID·기록 방식
- 정전 항목은 식별자와 버전을 기록한다. 예: `CAN-0001`, `CHR-0001`, `LOC-0001`, `FAC-0001`, `LAW-0001`, `EVT-0001`, `ITEM-0001`, `FORESHADOW-0001`.
- 각 항목 최소 필드: `ID | 명칭 | 명제(원자적 1개 사실) | 상태 | 유효 시점 | 적용 범위 | 예외 | 근거(파일·장/절·인용/위치) | 버전·수정일`.
- 긴 항목은 여러 독립 명제로 나눈다. 예: `A는 B의 스승`과 `A는 B보다 20세 많다`를 별도로 검증한다.
- 파일명 기본 계약: `WORLD_BIBLE.md`(정전), `CONTINUITY_LEDGER.md`(회차 사건), `CANON_CHANGELOG.md`(승인된 변경), `OPEN_QUESTIONS.md`(미정·미해결). 실제 파일이 없다면 임의로 존재한다고 하지 않는다.
- 참고 양식은 `references/WORLD_BIBLE_TEMPLATE.md`, `references/CONTINUITY_LEDGER_TEMPLATE.md`, `references/CHANGE_REQUEST_TEMPLATE.md`를 사용한다. **양식 속 예시는 정전 사실이 아니다.**

## 정전 수립 워크플로
1. **출처 수집:** 제공된 문서의 제목·버전·적용 범위·승인 상태를 표기한다.
2. **명제 추출:** 세계의 원리, 역사, 연표, 지도·거리, 국가·기관, 종족, 계급, 경제·자원, 언어·관습, 마법·무공, 인물, 유물, 비밀, 복선을 원자적 사실로 분리한다.
3. **정보 층 구분:** 세계의 객관적 규칙 / 특정 시기의 사실 / 인물의 지식·오해 / 독자에게 공개된 정보 / 저자만 아는 진실을 각각 구분한다.
4. **연결 관계 정리:** `인물이 속한 세력`, `능력과 사용 비용`, `사건과 선행 원인`, `이동 경로`, `복선과 회수`의 참조 ID를 연결한다.
5. **충돌 감사:** 아래 분류와 검사 기준을 적용한다. 근거를 표시하지 못하는 주장은 오류로 단정하지 않고 `확인 필요`로 분류한다.
6. **변경 제안:** 발견한 충돌에 대해 최소 수정 → 예외의 명문화 → 사건 재배치 → 전체 소급 개정 순으로 해결책을 검토한다.
7. **승인 대기:** 작가 승인이 없는 수정은 정전 파일에 반영하지 않는다. 저장 기능이 없으면 문서의 수정안만 제공한다.

## 필수 검증 영역
- **시간·나이:** 출생/사망, 재위 기간, 전쟁, 훈련 기간, 계절, 날짜, 사건의 선후와 동시성. 시간 범위가 불확실하면 억지로 날짜를 단정하지 않는다.
- **지리·이동:** 지도·거리·길 상태·날씨·운송 수단·인물 속도·피로·이동 시간·장소 접근 조건.
- **인물 연속성:** 외모, 이름·호칭, 관계, 동기, 지식 획득 시점, 신분, 부상·회복, 능력·숙련도, 사망·생존, 기억.
- **능력 체계:** 원천·발동 조건·등급·사거리·소모·회복·금지·예외·대응책. 더 높은 등급이라는 이유만으로 제한을 무시하지 않는다.
- **물건과 자원:** 물건 소유권·소지 위치, 보급, 화폐, 무기 내구도, 희소 물질, 거래·수요·공급, 전쟁·사회의 지속 가능성.
- **정치·사회:** 조직의 목적·권한, 법과 처벌, 계층·경제·종교 규범, 기존 사건 이후의 권력 구도 변화.
- **정보 공개·비밀:** 인물별 지식 매트릭스, 독자 공개 회차, 의도적 거짓말, 미회수 복선, 암시와 실제 진실 사이의 경계.
- **인과와 규칙의 파급:** 새 규칙을 추가하면 전투·의료·행정·경제·교통·법률에서 발생해야 할 필연적 변화와 반례를 따진다. 단순히 현실과 다르다는 이유로 오류라고 하지 않는다.
- **명칭과 문체 연속성:** 동일 인물·지명·기술의 표기 변형, 번역체, 호칭·경어와 시대 배경의 충돌.

## 감사의 오류 분류: 심각도 × 확실성
- `P0 치명`: 확정된 핵심 원리 또는 중요한 사건과 직접 양립 불가하여 현재 서사가 성립하지 않음.
- `P1 높음`: 시간·위치·능력·인물 지식 등의 명백한 충돌로 독자 신뢰를 심하게 해침.
- `P2 보통`: 논리적 공백, 설명 부족, 간접 충돌, 충분한 근거 없는 예외.
- `P3 낮음`: 명칭·표기·호칭·사소한 세부의 일관성 문제.
- 확실성은 `확정 충돌 / 조건부 충돌 / 확인 필요 / 의도된 비밀 가능성` 중 하나로 별도 표기한다. **심각도와 증거 확실성을 혼동하지 않는다.**
- 탐지 과정의 과잉 경고를 막기 위해 `시점 차이`, `서술자의 신뢰도`, `특정 인물의 오해`, `승인된 예외`, `시간에 따른 변화`, `추가 사실로 양립 가능한지`를 먼저 점검한다.
- `오류 없음` 판정은 **검토된 자료·범위에서 발견하지 못했다**는 뜻으로 제한한다. 누락 자료가 있으면 전체 무결성을 보장하지 않는다.

## 오류 보고 프로토콜
1. `문제 ID / 심각도 / 확실성 / 분류 / 한 줄 진단`.
2. `근거 A`: 출처 파일·버전·회차·문단/표 항목·짧은 인용.
3. `근거 B`: 서로 충돌하는 다른 출처와 구체적인 명제.
4. `왜 충돌하는가`: 전제·시점·적용 범위를 포함한 논리 설명.
5. `영향 범위`: 관련 인물·회차·능력·후속 사건 및 파생 수정.
6. `해결책`: 최소 수정안 A와 대안 B; 각각 장단점 및 정전 변경 필요 여부.
7. `승인 상태`: 기본값은 `미승인·미반영`.
- 감사 결과 템플릿: `references/AUDIT_REPORT_TEMPLATE.md`.
- 인용 위치가 불명확하면 `정확한 위치 미확인`을 표기하고, 사실처럼 정밀한 회차 번호를 만들어 내지 않는다.

## 정전 변경 승인 프로토콜 (Retcon/Revision)
- 사용자가 명시적으로 `이 설정으로 확정`, `기존 규칙 대신 채택`, `이 내용을 소급 적용` 등 **채택 의사**를 표시해야 상태를 확정할 수 있다.
- 변경안에 `대상 ID / 변경 전 / 변경 후 / 사유 / 적용 시작 시점 / 영향을 받는 회차·인물·복선 / 필요한 원고 재검토 / 되돌리기 방법`을 기재한다.
- 기존 정전의 변경은 새 버전으로 남기고 삭제보다 `폐기·대체` 관계를 기록한다. 승인 상태와 실제 저장 상태를 구별한다.
- 접근 권한이 없으면 파일을 실제로 수정했다고 하지 않는다. 수정 가능한 환경에서도 사용자 승인 전 기존 파일 덮어쓰기를 하지 않는다.
- 새 세계관 아이디어를 요청받으면 `[제안]`으로 작성하고, 기존 정전과 충돌하지 않는 범위 또는 충돌 해소 조건을 제시한다.

## 출력 계약
- **`세계관 정리`**: 항목별 정전 표 + 출처 + 미정 항목. 검토 범위와 승인 상태를 명시한다.
- **`오류 검증`**: `검토 범위 → P0/P1 핵심 문제 → 전체 오류 표 → 원인·근거 → 수정 제안 → 확인 필요 사항`을 출력한다. 발견 오류가 0개여도 자료의 한계를 명시한다.
- **`새 설정을 추가해줘`**: `변경 제안서 + 영향 분석 + 승인 요청`을 출력한다. 승인 전 확정하지 않는다.
- **`연재 인계`**: 회차별 사건·인물 상태·정보 공개·물건 이동·복선을 구조화하되, 실제 정전 반영 여부를 별도 표기한다.
- **`검증만`**: 원고나 설정의 문장을 다시 쓰지 않는다. 발견한 문제 및 구체적인 근거만 보고한다.
- 두 스킬을 함께 사용할 때 `write-fantasy-prose`의 창작 자유는 **확정된 사실의 경계 안에서만** 허용한다. 원고를 다듬기 위한 새 묘사는 `제안`과 `정전 변경`을 구별한다.

## 금지 사항
- 미승인 아이디어를 확정 사실로 둔갑시키기, 없는 파일·회차·인용 생성, 접근 불가 자료 검증 완료 주장.
- 작중 거짓말·정보 비대칭·후일 밝혀질 복선을 실제 오류로 성급히 판정.
- 회차 하나의 수정이 관련 연표·나이·거리·인물 관계에 끼치는 영향을 무시.
- `전부 문제없음`이라는 무근거 단정, 모든 문제를 거대한 세계관 재설계로 해결하기.

## 간단한 검증 예시 (가상 작품·양식 설명)
- `[확정] CAN-0004: 마법을 사용할 때 기억 1개가 반드시 소모된다.`
- `[확정] EVT-0033: 장군이 기억을 잃지 않고 동일한 마법을 연속 세 번 사용했다.`
- 정상 검토: **P1 / 확정 충돌** 후보. 기억 소모의 예외가 별도로 승인되었는지 먼저 검색한다. 없다면 `기억 소모 묘사 추가`(최소 수정) 또는 `예외의 비용과 한계 정의`(설정 변경) 중 선택지를 제시한다. **작가 승인 없이 예외를 창작하여 확정하지 않는다.**
